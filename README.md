# ReelBot

Исходный код проекта хранится в открытом GitHub-репозитории; сам Telegram-бот закрыт и доступен только владельцу. Он собирает вертикальные Reels с русскими субтитрами. Веб-приложение проекта также сохранено.

## Активный процесс обработки

- `cloudflare/reelbot-gateway.js` — исходник Cloudflare Worker v5. Он принимает Telegram webhook, хранит состояние и очередь в KV `STATE`, защищает внутренние `/runner/*` маршруты токеном и проксирует загрузку исходников и отправку готового видео.
- `runner.py` — Python-runner, который GitHub Actions запускает по расписанию примерно каждые 5 минут и вручную через **Actions → ReelBot runner → Run workflow**. Он забирает задания у Worker, скачивает видео во временную папку runner, монтирует ролик и отправляет его в Telegram. Исходные видео и готовые ролики не сохраняются в репозитории или KV.
- `requirements.txt` — зависимости runner: Whisper, OpenCV, NumPy, Pillow и requests.
- `.github/workflows/reelbot-runner.yml` — активный workflow. У него только разрешение `contents: read`; credentials checkout не сохраняются.

`runner/poll.ts` и `server/telegram.ts` — прежняя TypeScript-реализация обработчика. Активный Actions workflow больше её не запускает.

## Возможности

Runner поддерживает короткие русские блоки до трёх слов по Dropbox-спецификации; более старые пресеты сохраняют прежнюю фразовую группировку. Шесть активных стилей: `glass` (тёмно-серая плашка, 60%), `powder` (пудровая, 95%), `fuchsia` (ключевые блоки, 75%), `olive` (ключевые блоки, 85%), `echo` (двойной текст, 54%) и `mixed` (розовое/жёлтое ключевое слово, 60%). Прозрачность по умолчанию берётся из стиля и не перезаписывается общим значением; её можно явно настроить через `/plate-opacity`. По умолчанию субтитры стоят внизу, около y=1490; через `/caption-position` можно выбрать верх или автоматическое положение.

Настройки Telegram: `/styles` — присылает шесть Dropbox-стилей с примерами и кнопками; `/plate-opacity` — явная настройка плотности плашки (20–80%), `/font` — Inter, Montserrat или Oswald, `/caption-position` — низ, верх или автоматическое размещение. Шрифт кириллицы задаётся в ASS и передаётся FFmpeg через `fontsdir`.

Для проекта доступны GIF/видео-вставки и текстовые плашки как отдельные слои до рендера. `/layers`, `/undo` и `/remove layer N` показывают и меняют эти слои. `/findinsert <тема>` ищет небольшие GIF и видео в Wikimedia Commons без личного API-ключа, показывает только распознанные метки CC0/Public Domain/CC BY, сохраняет автора и лицензию и предлагает выбрать результат; после сборки отдельным сообщением приходит копируемый список авторства и ссылок. Это не каталог всех мемов или гарантированный источник современных кинофрагментов. Запрос к Commons из среды разработки вернул HTTP 403; Worker уже опубликован, но сам поиск ещё не проверен через Telegram.

Можно выбрать `/motion` (обычные наезды, без движения, усиленные наезды), `/speed` (×1, ×1.1, ×1.2, ×1.3, ×1.5) и `/filter` (девять цветовых пресетов, включая исходный вариант). Ускорение применяется до распознавания, а обработка звука сохраняет высоту голоса. Движение камеры в текущей версии — это масштабирование/наезды; панорамы, орбита и кран пока не реализованы.

`/script <тема>` ставит задание на три оригинальных варианта начала, сценарий и план кадров, если настроен `ANTHROPIC_API_KEY`; без него бот выдаёт только общий каркас. Бот не ищет чужие ролики в Instagram. После готового ролика `/edit <ID>` открывает исходный проект, `/caption-edit <секунда> <текст>` заменяет ближайшую фразу, а вставки и плашки можно менять. Затем бот скачивает исходники и пересобирает MP4 целиком: готовой монтажной шкалы, постоянного предпросмотра и рендера только изменённого слоя пока нет. Референс видео по-прежнему даёт приближённый зум.

Dropbox-спецификация задаёт шесть стилей: Glass, Powder, Fuchsia, Olive, Echo и Mixed Key Words. Общие параметры — 1080×1920, жирный текст 58 px по центру внизу (примерно y=1490), не более трёх слов в блоке и завершение каждого блока не позже следующего. Ключевые блоки для Fuchsia/Olive — первый, затем каждый третий при слове от шести букв.

## Секреты и доступ

Не добавляйте в репозиторий значения токенов, Telegram ID, webhook-секреты, Telegram file IDs, видео или готовые ролики.

- Cloudflare Worker secrets: `TELEGRAM_BOT_TOKEN`, `ALLOWED_TELEGRAM_USER_ID`, `TELEGRAM_WEBHOOK_SECRET`; binding: `STATE`.
- GitHub Actions secrets: `TELEGRAM_BOT_TOKEN`; `GATEWAY_URL` — адрес Worker (если секрет не задан, workflow использует текущий публичный URL); `ANTHROPIC_API_KEY` — необязательный ключ языковой модели для полноценного сценария и подробного разбора текста. Это не вход в Instagram: бот не ищет автоматически ролики других авторов. Без ключа он даёт общий каркас сценария и простую предварительную проверку начала, без числового балла.

Значения хранятся только у провайдера. Runner передаёт сообщения через защищённые Worker-маршруты; не добавляйте значения секретов в логи.

## Проверки и разработка

Изменения опубликованы в GitHub `main`, коммит `0d0f889` (`Add six subtitle styles and karaoke color control`). Cloudflare Worker `reelbot-gateway` обновлён 19 ноября 2026 года; deployment ID: `a7b8a467-b8e4-4cde-9a2c-0a02421cf4e0`. `/health` вернул HTTP 200 и `storageConfigured: true`; настройки показывают сохранённые KV-привязку `STATE` и секреты. Команды `/styles`, `/karaoke-color` и `/font` пока не проверены отправкой сообщений в живой Telegram-чат.

- `python -m py_compile runner.py` — синтаксис runner.
- `node --check cloudflare/reelbot-gateway.js` — синтаксис Worker.
- `python3 -m unittest discover -s tests -v` — тесты выбора позиции, изменения фраз, шрифта, прозрачности, всех шести дизайнов и karaoke-времён.
- `node --test tests/reelbot-worker.test.mjs` — тесты Telegram-команд, передачи цвета слова, шести кнопок и примеров, слоёв, сценарных задач и фильтрации лицензий.
- `pnpm install --frozen-lockfile`, `pnpm check`, `pnpm test` — веб-приложение.
- В `assets/fonts/` лежат шрифты с кириллицей и лицензии SIL OFL. FFmpeg получает эту папку через `fontsdir`; статические regular/bold-файлы помогают libass точно выбирать нужный шрифт на разных runner. Шесть изображений для Telegram находятся в `assets/caption-previews/`; их можно пересоздать командой `python3 tools/generate_caption_previews.py`, которая использует тот же генератор ASS, что и ролики.
- Для обычного локального видеотеста нужны FFmpeg, зависимости из `requirements.txt` и модель faster-whisper.

GitHub Actions может запускаться с задержкой; интервал проверки не обещает мгновенный ответ. Стандартный лимит входного Telegram-видео — 20 МБ, а готовый ролик должен быть меньше 49 МБ.
